# I-03 轻量关联分析 —— 技术方案

> 版本：v1.0 ｜ 阶段：POC ｜ 对应功能：F-08 / F-11（关联分析 + 告警分级 SLA）
> 关联：`docs/I-01-探针接入与ECS归一-技术方案.md`、`docs/I-02-统一检索与存储增强-技术方案.md`
> 状态：**已实现并实测通过**

## 1. 目标与范围
在「统一存储检索」之上建立**轻量关联分析**能力：从归一化探针事件中按规则做关联，产出**带级别的告警**，为 I-04（MISP 情报）、I-05（SOAR 响应）、I-07（态势大屏）提供数据源。

- 采用**规则化（rule-based）关联**，POC **不引入 Metron** 流式关联（PRD 非目标）。
- 实现方式：独立服务 `services/correlator/correlator.py`（**纯标准库**，零第三方依赖），周期/按需从 `ssp-events` 读取事件，输出到独立索引 `ssp-alerts`。

## 2. 架构与数据流
```
ssp-events（统一检索别名：suricata + zeek + wazuh）
        │  ① 按窗口拉取（@timestamp range）
        ▼
[关联引擎 correlator]
        │  ② 逐规则分组聚合 → 实体级告警候选
        │  ③ 分级 + 升级因子（资产重要度 / 情报命中）
        │  ④ 资产富化（ssp-assets 按 IP 匹配）
        │  ⑤ 威胁情报富化（I-04 钩子；缺失则标记"情报未匹配"）
        ▼
ssp-alerts（分级告警索引，独立）
```
- 服务端口 `:8091`，提供 `POST /correlate`（跑一次）、`GET /alerts`、`GET /rules`、`GET /health`。
- 支持后台周期关联（`CORR_INTERVAL_SECONDS`，默认 60s；`0` = 仅手动触发）。
- 也支持单次 CLI：`python3 correlator.py --once`。

## 3. 关联窗口（含回放锚定）
窗口 `[end - WINDOW_MINUTES, end]`（默认 30 分钟）。窗口右端 `end` 的确定：
- 若最新事件在"现在"附近 → 锚定 `now`（**实时**模式）；
- 若数据陈旧（如回放/演示 fixtures）→ 锚定**最新事件时间**（**replay** 模式），保证陈旧数据仍可关联。

> 该设计使同一引擎既能跑实时流，也能跑历史回放 Demo，无需改配置。

## 4. 关联规则
| 规则 | 名称 | 判定 | 基础级别 |
|---|---|---|---|
| R-001 | 跨源外部IP关联 | 同一外部 IP 出现在 ≥2 个探针来源 | P2（≥3 源 → P1） |
| R-002 | SSH暴力破解/异常认证 | Wazuh `authentication_failures` 类规则，源自外部 IP | P1 |
| R-003 | 恶意载荷下载 | Suricata 带 `file.hash.sha256` 或命中恶意下载域名 | P0 |
| R-004 | 主机文件完整性异常 | Wazuh FIM（`syscheck`）检出可疑文件落地 | P1 |
| R-005 | 内网主机外联聚合 | 同一内网源连 ≥N（默认 3）个不同外部 IP | P3 |
| R-006 | IDS高危签名告警 | Suricata `event.kind=alert`（单源签名命中） | P2 |
| R-007 | 可疑C2域名查询 | DNS 查询名（`dns.question.name`）命中 C2/恶意特征 | P1 |

- **外网 IP 判定**：显式排除 RFC1918 / 环回 / 链路本地 / 组播 / 
  docker 网段，**不用** `ipaddress.is_private`（Python 会把 `198.51.100.0/24`、`203.0.113.0/24`
  等 TEST-NET 判为 private，会误伤）。
- **良性外网白名单**：`8.8.8.8 / 8.8.4.4 / 1.1.1.1 / 114.114.114.114` 等跳过（避免把公共 DNS 当攻击目标）。

## 5. 告警分级模型（PRD §12）
| 级别 | SLA | 语义 | severity | risk_score |
|---|---|---|---|---|
| P0 | 秒级（0s） | 已知恶意/高危 | critical | 90 |
| P1 | 1 分钟 | 主机失陷特征/重伤 | high | 70 |
| P2 | 10 分钟 | 单源高危/疑似 | medium | 50 |
| P3 | 30 分钟 | 一般可疑 | low | 30 |

**升级因子**（在基础级别上提升）：
1. 命中**重要资产**（`importance ∈ {重要, 核心}`）→ 升 1 档；
2. **威胁情报命中**（I-04）→ 直接置 P0。

## 6. 输出：`ssp-alerts` 索引
- 物理索引 `ssp-alerts`（**无别名** —— 避免"索引名 = 别名名"冲突；这是实测踩坑，见 §8）。
- 模板 `config/opensearch/ssp-alerts-template.json`：`index_patterns: ["ssp-alerts"]`、`priority 300`、
  `dynamic: false`（显式声明字段）。**不匹配** `ssp-ecs`（已收敛为三个探针前缀），故不会进 `ssp-events`。
- 关键字段：`event.{kind,severity,risk_score}`、`ssp.alert.{id,rule_id,grade,sla_seconds,sla_label,status,
  generated_at,due_at,first_seen_at,last_seen_at,escalation_factors}`、`source.ip`、`destination.ip`、
  `related.{log_sources,event_count,event_ids}`、`asset.*`、`threat.*`、`message`。

## 7. 关键设计：**防自反馈**
关联引擎从 `ssp-events` 读事件、往 `ssp-alerts` 写告警。若别名或模板用通配 `ssp-*`：
- 统一检索会把资产/告警当事件返回（口径污染）；
- 引擎会把**自己刚写出的告警再读一遍**，形成自反馈循环。

**双重防护**：
1. 模板 `index_patterns` 收敛为 `ssp-suricata-* / ssp-zeek-* / ssp-wazuh-*`；`init-alias.sh` 同步收敛；
2. 引擎侧按 `fields.log_source` **白名单**（`suricata,zeek,wazuh`）过滤，非探针来源一律丢弃。

**幂等 upsert**：告警 `_id = sha1(rule_id + entity_key)[:24]`。同一规则 + 同一实体 → 唯一告警；
重复运行只更新 `last_seen_at / event_count`，并**保留人工处理结果**（`status / response_action / ticket_id`），
级别取"更紧急者"。

## 8. 实测结果（9 条真实探针事件）
- 关联产出 **8 条分级告警**：2×P0（R-003 载荷下载）、4×P1（R-001 三源关联 / R-002 暴破 / R-004 FIM / R-007 C2 域名）、2×P2（R-001 两源 / R-006 IDS 签名）。
- **幂等**：重复运行 `created=0 / updated=8 / errors=0`。
- **升级因子**：命中"生产Web服务器-web-prod-01（重要）"的 R-001/R-002/R-004 → 升为 P0，R-006 → P1；
  命中"一般"资产的不升。
- **防污染**：`ssp-events/_count` 恒为 9，别名仅挂三个探针索引。

## 9. 踩坑记录
- 🐞 **fixtures 时间轴错位**：`logs/zeek/conn.log` 的 `ts` epoch 为 `1789818001`（=11:40Z），
  而 suricata/wazuh fixtures 为 `11:20(+0800)=03:20Z`，且 zeek 自身 `#open 2026-09-19-11-20-00` 头
  证明其 `ts` 不可能晚于 11:20 → 修正为 `1789788001/12/25`（=03:20:01/12/25Z），使 9 条事件落在 30 分钟窗口内。
  （不修会导致关联窗口只覆盖单一来源、SLA/攻击地图一并失真。）
- 🐞 **索引名不能等于别名名**：`ssp-alerts` 同时作 index 与 alias → `duplicates ... conflicts with index`，bulk 全失败。改为**仅用索引名 `ssp-alerts`、不设别名**。
- 🐞 **本机访问统一 `--noproxy '*'`**；urllib 走代理需 `no_proxy` 环境变量。

## 10. 与后续事项的接口
- **I-04**：实现 `services/correlator/threat_intel.py`，暴露 `match_alert(evt) -> threat dict`；
  引擎自动加载（缺失即降级为"情报未匹配"，不阻断）。
- **I-05**：消费 `ssp-alerts`（`ssp.alert.grade` 达阈值 → 生成拉黑草稿）；审批/执行后回写
  `ssp.alert.status / response_action`——upsert 会保留这些字段，不会被关联覆盖。
- **I-07**：大屏直接聚合 `ssp-alerts`（等级分布、TOP、SLA 达成率）。
