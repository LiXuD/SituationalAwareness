## 2. 资产数据模型

### 2.1 资产是「独立域」，不是日志事件

资产与 I-01/I-02 的探针事件（Suricata/Zeek/Wazuh）是**不同的数据域**：

- 事件是「发生时序记录」（ECS：`@timestamp` + `event.*` + `source/destination.ip` …），来自探针，写入 `ssp-<source>-YYYY.MM.dd`，挂在别名 `ssp-events`。
- 资产是「被保护对象的事实描述」（名称/IP/类型/重要度/风险评分/责任人…），**来源仅手工+Excel**，写入独立索引 `ssp-asset`，挂在别名 `ssp-assets`。

两者分库、分别名，互不污染；下游 I-07 大屏分别从 `ssp-events`（攻击地图/告警 TOP）与 `ssp-assets`（资产热力）取数，再在视图层融合。

### 2.2 字段定义（索引 `ssp-asset` mapping，dynamic:false）

| 字段 | 类型 | 必填 | 枚举 / 规则 | 说明 |
|---|---|---|---|---|
| `asset_id` | keyword | 否（留空自动生成 uuid4） | 全局唯一；导入列「资产编号(可选)」可指定（存在则 upsert） | 稳定 ID，大屏按此聚合 |
| `name` | text + keyword | **是** | ≤128 | 资产名称 |
| `ip` | ip | **是** | IPv4/IPv6 格式校验 | 资产 IP |
| `asset_type` | keyword | 否 | 服务器/网络设备/安全设备/终端设备/应用系统/数据库/其他（缺省「其他」） | 资产类型 |
| `importance` | keyword | **是** | 核心 / 重要 / 一般 | 重要度分级 |
| `importance_score` | integer | 自动 | 核心=3，重要=2，一般=1 | 重要度权重，**大屏着色用** |
| `risk_score` | integer | **是** | 0–100 | 风险评分，**大屏着色用** |
| `owner` | keyword | 否 | — | 责任人 |
| `department` | keyword | 否 | — | 所属部门 |
| `location` | keyword | 否 | — | 位置/机房 |
| `os` | keyword | 否 | — | 操作系统 |
| `tags` | keyword(array) | 否 | 逗号分隔 | 标签 |
| `description` | text | 否 | — | 备注 |
| `created_at` / `updated_at` | date | 自动 | ISO8601 UTC | 时间戳 |

> 重要度与风险评分是 I-07 资产热力的两个坐标轴：`importance_score × risk_score` 决定着色强度与排序。

### 2.3 索引与模板

- 索引名：`ssp-asset`（单索引，POC 不按天滚动）。
- 别名：`ssp-assets`（资产检索统一入口）。
- 模板：`config/opensearch/ssp-asset-template.json`，`index_patterns: ["ssp-asset*"]`，`priority: 300`，显式 mapping（见上），下发脚本 `scripts/asset-apply-template.sh`。
- **关于 `ssp-events` 别名**：`ssp-ecs` 模板 `index_patterns: ["ssp-*"]` 理论上也会匹配 `ssp-asset`。实测（OpenSearch 2.13，见 §6.2）在更高优先级模板已定义 `aliases` 时，`ssp-asset` 仅挂 `ssp-assets`、**未**被并入 `ssp-events`，未污染事件域。此为版本相关行为，已在 §7 标注风险。

## 3. REST 接口表

服务监听 `:8090`（容器内 `http://opensearch:9200` 连同一集群）。所有响应带 CORS 头（`Access-Control-Allow-Origin: *`），支持浏览器直连。

| 方法 | 路径 | 说明 | 关键参数 / 体 |
|---|---|---|---|
| GET | `/` | 服务落地页（含 API 列表） | — |
| GET | `/healthz` | 健康检查（含 OpenSearch 连通性） | — |
| GET | `/api/assets` | 列表（关键字/重要度过滤 + 分页） | `q`、`importance`、`page`、`size` |

| PUT | `/api/assets/{id}` | 修改 | JSON：需更新字段 |
| DELETE | `/api/assets/{id}` | 删除 | — |

| GET | `/api/assets/template.xlsx` | 导入模板下载 | — |

错误响应统一：`{"ok":false,"error":"...","errors":[{"row","field","reason"}]}`。

模板：`services/asset/templates/asset-import-template.xlsx`（开发期由 `scripts/gen-asset-template.py` 用托管 venv 的 openpyxl 生成，含「资产导入模板」+「字段说明」两个 sheet）。

## 5. Excel 导入「全成或全败」回滚实现原理

流程（`services/asset/asset_server.py::do_import_xlsx`）：

1. **解析**：`parse_xlsx()` 读取 xlsx → 行列表；表头缺失必需列直接 400。
2. **全量预校验**（关键，先不写任何文档）：逐行 `validate_row()`，收集所有非法单元格到 `errors`（`{row, field, reason}`）。
   - 必填：名称/IP/重要度/风险评分；
   - IP：`ipaddress.ip_address` 校验；
   - 重要度：枚举 {核心,重要,一般}；
   - 风险评分：`int` 且 0–100。
3. **任一非法 → 整批拒绝**：返回 `422` + `errors` 明细，**保证一个文档都不写入**（存量为 N，导入后仍为 N）。
4. **全部合法 → 批量写**：`bulk_index()` 用 `_bulk` 一次性写入；检查 `errors` 字段，若个别 item 失败则收集成功 `_id` 并 `rollback_bulk()` 删除已写部分，返回 422 + 失败明细（极端 infra 失败路径也保证全成或全败）。
5. 成功返回 `200 {ok:true, imported:N}`。

> 设计要点：校验与写入**两阶段分离**，把「数据正确性」错误挡在写入之前，使最常见的「含非法行」场景天然零副作用；bulk 级失败再补一道回滚，覆盖 infra 异常。

## 6. 实测结果（真实命令与输出，未编造）

环境：macOS / Docker Desktop 29.7.2 / Compose v5.4.0；栈已运行；OpenSearch :9200 已有 ssp-suricata=4 / ssp-zeek=3 / ssp-wazuh=2。

### 6.1 compose 合并校验
```bash
export PATH=/usr/local/bin:$PATH
cd deploy && docker compose config        # exit=0
docker compose config --services          # opensearch asset logstash filebeat opensearch-dashboards ui
```
根文件精确插入 `asset/compose.yml` 后 include 合并通过，`--services` 含 `asset`。

### 6.2 下发资产模板
```bash
bash scripts/asset-apply-template.sh       # {"acknowledged":true}
curl -s localhost:9200/_index_template/ssp-asset | python3 -c "查 priority/aliases/mappings"
# priority=300  aliases={'ssp-assets':{}}  nprops=15
```
> 注：首次下发曾出现模板仅存 settings 的残留现象，经 `DELETE + 重新 PUT` 后完整（priority 300 / alias ssp-assets / 15 字段）。已在交付前固化正确状态。

**别名污染实测**：`ssp-asset` 仅挂 `ssp-assets`；`ssp-events` 仍只含 `ssp-zeek-…/ssp-wazuh-…/ssp-suricata-…`（count=9，未变），资产未污染事件域。

### 6.3 起服务 + 健康检查
```bash
docker compose up -d asset
curl -s -o /dev/null -w '%{http_code}' http://localhost:8090/healthz   # 200
curl -s http://localhost:8090/healthz
# {"status":"ok","opensearch":"http://opensearch:9200","opensearch_reachable":true}
```

### 6.4 手工新增 3 条 + 真实落库
```bash
# 手工 POST 3 条（含 1 条自动生成 ID）
curl -s -X POST localhost:8090/api/assets -d '{"asset_id":"MAN-1","name":"核心数据库","ip":"10.20.30.10","importance":"核心","risk_score":80,...}'
curl -s "localhost:9200/ssp-asset/_count"   # {"count":3}
curl -s "localhost:9200/ssp-asset/_doc/MAN-1"   # found=true，_source 完整含 importance_score=3
```

### 6.5 合法 Excel 导入（count 3 → 8）
```bash
curl -s -X POST localhost:8090/api/assets/import -F "file=@samples/assets/valid-assets.xlsx"
# {"ok":true,"imported":5,"message":"成功导入 5 条资产"}
curl -s localhost:9200/ssp-asset/_count     # {"count":8}
# AST-001..AST-005 真实落库，importance_score/risk_score 映射正确
```

### 6.6 含非法行 Excel 导入（回滚生效，count 不变）
```bash
curl -s -o /tmp/inv.json -w 'HTTP %{http_code}\n' -X POST localhost:8090/api/assets/import -F "file=@samples/assets/invalid-assets.xlsx"
# HTTP 422
# errors: 第3行 IP地址 非法(999.1.1.1) / 第4行 重要度枚举非法(极高) /
#         第5行 风险评分超界(150) / 第6行 资产名称为空
curl -s localhost:9200/ssp-asset/_count     # {"count":8}  （未变）
curl -s localhost:9200/ssp-asset/_search -d '{"query":{"prefix":{"asset_id":"BAD-"}}}'  # BAD- docs written = 0
```
回滚与逐行错误报告均验证通过。

### 6.7 HTTP 200 / 模板下载 / 过滤
```bash
curl -s -o /dev/null -w '%{http_code}' http://localhost:8090/            # 200
curl -s -o /dev/null -w '%{http_code}' http://localhost:8088/assets.html # 200
curl -s -o /tmp/tpl.xlsx -w 'HTTP %{http_code} type=%{content_type} size=%{size_download}\n' localhost:8090/api/assets/template.xlsx
# HTTP 200 type=application/vnd.openxmlformats-officedocument.spreadsheetml.sheet size=6696
curl -s "localhost:8090/api/assets?importance=核心&size=50"  # 核心数=3 [AST-001,AST-002,MAN-1]
```

### 6.8 PUT / DELETE / CORS 预检
```bash
curl -s -X PUT localhost:8090/api/assets/MAN-1 -d '{"risk_score":75}'  # ok, risk_score=75（已回写 80）
curl -s -X DELETE localhost:8090/api/assets/TMP-X                      # ok, deleted
curl -X OPTIONS localhost:8090/api/assets -H 'Origin: http://localhost:8088' -w '%{http_code}'  # 204
curl -s localhost:9200/ssp-asset/_count   # {"count":8}  （TMP-X 已删，最终 8 条样本资产）
```

**结论**：PRD §9 两条 EARS（Event-driven 更新资产库、Unwanted 导入失败回滚+错误行）均经真实命令验证通过。

## 7. 已知限制与未做项

1. **鉴权/权限**：POC 未做真实鉴权，资产管理员「增删改」接口直接开放（PRD §11 允许先不做，明确为已知限制）。生产需接入 OpenSearch/Dashboards 或网关层鉴权。
2. **审计日志**：资产变更未留审计日志（谁/何时/改了什么）。后续阶段补。
3. **`ssp-events` 别名行为**：资产索引命名 `ssp-asset` 会匹配 `ssp-ecs` 模板的 `ssp-*` 模式。**已独立复验（2026-09-19）**：`_cat/aliases/ssp-events` 只列出 `ssp-suricata-*` / `ssp-zeek-*` / `ssp-wazuh-*` 三索引，`ssp-events/_count = 9`（8 条资产未计入），当前无污染。但属版本相关行为；若升级 OpenSearch 后发生别名合并，应把 `ssp-ecs` 的 `index_patterns` 收窄（如显式列表或 `ssp-<source>-*`）以排除资产索引。此文件不在本事项修改边界内，故未改。
4. **动态映射**：资产索引 `dynamic:false`，导入/新增写入的字段必须落在模板 mapping 内；新增字段需同步改模板并 re-PUT。
5. **并发 upsert**：导入同一「资产编号」在批内后行覆盖前行（幂等 upsert）；跨批重复编号则更新既有文档。符合预期。
6. **大屏联动**：I-07 尚未实现；本事项仅保证资产数据可读（`ssp-assets` 别名 + 稳定 `asset_id` + 重要度/风险字段），供大屏直接聚合。
7. **样本数据**：自测后 `ssp-asset` 保留 8 条样本资产（3 手工 + 5 导入），便于大屏联调；如需重置，仅可删 `ssp-asset*`（严禁删 ssp-suricata*/zeek*/wazuh*）。
