# PRD — 一体化安全态势感知平台（阶段一 / POC）

> 版本：v1.0 ｜ 阶段：POC（技术预研）｜ 日期：2026-09-18
> 关联文档：需求规划基线 v1.0、需求池 v1.1

## 1. 背景
当前安全能力分散在 Suricata / Zeek / Arkime / Wazuh / OpenSearch / MISP / Shuffle 等独立开源组件中，缺乏统一接入、统一视图与统一响应，安全运营割裂、效率低、易漏判。本项目目标是构建一体化态势感知平台，将分散组件整合为"统一采集 → 统一存储检索 → 统一关联分析 → 统一资产/情报 → 统一 SOAR 响应 → 统一态势大屏"的闭环。

## 2. 目标与非目标
**目标（POC）**
- 验证组件整合可行性，端到端跑通"探针告警 → MISP 情报匹配 → Shuffle 自动拉黑/工单"闭环并在态势大屏可见。
- 建立统一数据底座（ECS 公共 Schema）与统一资产库雏形。

**非目标（本阶段不做，后续阶段）**
- 多分支汇聚（千兆专线已确认，架构预留）
- 外部日志源接入（防火墙/WAF/syslog/AD，预留适配器）
- 信创/国产化适配
- 生产高可用、Metron 流式关联、资产测绘自动化

## 4. 用户故事
- 作为**分析师**，我希望在一个大屏看到全网攻击地图、告警 TOP、资产热力、SLA 达成率，以便秒级掌握整体态势。
- 作为**分析师**，我希望告警能自动关联 MISP 威胁情报并分级，以便优先处理高危事件。
- 作为**运维**，我希望拉黑动作在提交前经我确认，以免误杀正常业务 IP。
- 作为**资产管理员**，我希望能手工录入或 Excel 批量导入资产，以便资产库尽快可用、驱动资产热力。
- 作为**测试**，我希望有清晰的验收标准与边界场景，以便客观判定 POC 是否通过。

## 6. 流程说明（端到端闭环）
1. 采集层探针产生原始事件 → Logstash 按 ECS 归一写入 OpenSearch；Arkime 存 PCAP。
2. 分析层：轻量关联规则 + MISP 情报实时比对，产出带级别的告警。
3. 响应层：达到自动处置级别的告警触发 Shuffle 剧本，生成**拉黑草稿**（不自动提交）。
4. **运维人员**在审批界面确认 → 提交拉黑（落黑点：防火墙 API / 本机 iptables / 动态写 Suricata 规则，POC 确定其一）。
5. 结果回写，态势大屏实时刷新（攻击地图标记、告警状态、SLA 计时）。

## 7. 交互说明
- **态势大屏**：四类视图切换/同屏；告警可下钻到原始日志与 PCAP。
- **资产库**：列表 + 新增表单 + Excel 导入入口（模板下载）；导入后资产热力刷新。
- **拉黑审批**：草稿列表 → 详情（命中情报、影响面）→ 确认/驳回；确认后状态变更为"已提交"。

## 8. 数据指标（首版大屏）
| 指标 | 口径 |
|---|---|
| 攻击地图 | 按源 IP 地理定位聚合告警，热力/散点 |
| 告警 TOP | 按级别/类型/资产 TOP N 排序 |
| 资产热力 | 按资产重要度 × 风险评分着色 |
| SLA 达成率 | 各级别"实际响应时延 ≤ 级别 SLA"的告警占比 |

## 9. 验收标准（EARS）
- **Ubiquitous**：系统应统一以 ECS Schema 存储所有探针事件。
- **Event-driven**：当探针检测到已知攻击（Suricata 规则）或真实流量回放触发告警时，系统应生成统一格式告警事件并写入 OpenSearch。
- **Event-driven**：当告警进入分析层时，系统应将源 IP/域名/哈希与 MISP 情报实时比对并标注命中。
- **Unwanted**：若 MISP 不可达，则系统应照常产生告警并标记"情报未匹配"，不得阻断主流程。
- **State-driven**：当告警达到自动处置级别时，Shuffle 应生成拉黑草稿；**系统不应自动提交**，除非运维人员确认。
- **Event-driven**：当运维人员确认拉黑，系统应执行落黑动作并回写，且大屏状态可见。
- **Ubiquitous**：系统应在态势大屏展示攻击地图、告警 TOP、资产热力、SLA 达成率四类视图。
- **State-driven**：系统应按告警级别在 30 分钟 / 10 分钟 / 1 分钟 / 秒级内完成对应响应 SLA，并统计达成率。
- **Event-driven**：当资产通过手工或 Excel 导入，系统应更新资产库并使资产热力图刷新。
- **Unwanted**：若 Excel 导入失败，系统应回滚本次导入并报告错误行，不影响存量资产。

## 10. 边界与异常
- 情报平台不可达：告警照常，标记"情报未匹配"。
- 审批超时：草稿保留，不自动提交。
- Excel 导入部分失败：回滚 + 错误行报告。
- 探针断连：大屏标记该数据源异常，不影响其他源。
- 落黑动作失败：记录失败原因，告警保持"待处置"，通知运维。

## 11. 权限规则
- 分析师：查看 / 研判 / 下钻
- 运维：审批并提交拉黑
- 资产管理员：资产增删改
- 技术负责人：平台配置 / 探针管理

## 12. 数据口径
- **ECS Schema**：统一字段（@timestamp, source.ip, destination.ip, event.kind, event.category, threat.indicator 等）。
- **告警 4 级**：P0 秒级 / P1 1 分钟 / P2 10 分钟 / P3 30 分钟（级别由关联规则+情报命中判定）。
- **SLA 计时**：从告警生成时刻起到响应动作（提交拉黑/工单）完成。

## 13. 度量（POC 轻量埋点）
- 闭环时延（告警生成→拉黑提交）
- SLA 达成率
- 各探针事件吞吐
