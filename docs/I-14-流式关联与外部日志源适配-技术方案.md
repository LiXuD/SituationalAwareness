## 一、背景与目标

### 1.1 现状（问题）

1. **关联是批式的**：`correlator` 按窗口扫描 OpenSearch（周期默认 60s），从中招到告警落库是**分钟级**；
   跨源关联必须等事件全部落库后才可能命中。
2. **Kafka 汇聚层已就位但只被"消费一次"**（I-13）：所有分支/总部事件都经 `ssp-raw` 汇聚，
   再做 ECS 归一 → **实时消费事件流的采集侧成本已为零**，只差一个消费者。
3. **外部日志源进不来**：防火墙 / WAF 等第三方日志（syslog / CEF / JSON）没有入口，
   攻击面覆盖不完整。

### 1.2 目标

| 编号 | 目标 | 可观测结果 |
|---|---|---|
| G1 | **流式关联**：新增 Kafka 消费者，实时消费事件流并做规则匹配与分级 | 从事件产生到 `ssp-alerts` 落库**从分钟级降到秒级**（实测 1.05~1.19s，流式段 11~17ms） |
| G2 | **外部日志源适配**：第三方日志按 `fields.log_source`/`fields.branch` 打标后投递本汇聚层 | 新增一类源**不改中心端口/汇聚层**即可入库、可检索、**可被关联消费** |
| G3 | **不破坏现状**：批式 correlator、测绘、大屏、SOAR 保持可用 | `make verify` **21/21 全绿**（原 16 项 + 新增 5 项） |

### 1.3 非目标（本期明确不做）

- Flink 集群化 / exactly-once（D1 选项 A，见 §二；接口已预留替换点）
- 流式 UEBA / 学习型异常检测
- 外部源字段全量映射（POC 跑通 syslog / CEF / JSON 三类入口 + 防火墙方言）
- **替换**批式 correlator（两者**并存**，靠幂等 `_id` 去重）

## 二、关键设计决策（D1~D4 落定）

| # | 决策点 | 计划选项 | **落定** | 理由 |
|---|---|---|---|---|
| **D1** | 流式实现形态 | A Flink ／ B 轻量消费者 ／ C 先 B 后 A | **C → 本期交付 B** | x86 私有化交付不能依赖 pip / 重量组件；`services/common/kafka_lite.py` 用**标准库**实现协议子集，`kernel.evaluate()` 即引擎替换点 |
| **D2** | 批式是否保留 | 保留并存 ／ 被流式替代 | **保留并存** | 流式负责"秒级初判"（短窗口），批式负责"窗口内跨源深度关联"（30min）；两者写同一索引、共用同一份规则实现 |
| **D3** | 首个外部源 | 防火墙 syslog ／ WAF ／ AD | **防火墙 syslog（RFC3164/5424）+ WAF CEF + 通用 JSON 三入口** | 覆盖主流形态；防火墙方言（Cisco ASA deny/allow 行）作为范例在 Logstash 侧归一 |
| **D4** | 优先级 | 先 L1 ／ 先 L2 | **L1 → L2 同期交付** | L2 复用 L1 的汇聚层与归一产出，先后无耦合，一次交付可端到端验证"外部源参与关联" |

## 三、总体架构

```
                           ┌──────────────── 中心汇聚层（I-13，已在位）────────────────┐
采集端                     │                                                        │
 Filebeat(总部 hq)  ─┐     │                                                        │
 Filebeat(sh-01/bj-01)├──▶──┼──▶ Kafka  ssp-raw  ──▶ Logstash(ECS 归一 + 地理富化)   │
 外部源适配器(L2)   ─┘     │        │                     │                            │
                           │        │                     ├──▶ OpenSearch            │
                           │        │                     │      ssp-<源>-日期         │
                           │        │                     │      （检索 / 批式关联）     │
                           │        │                     └──▶ Kafka  ssp-ecs  ◀── I-14 新增旁路
                           │        │                              │  （归一后事件流）   │
                           └────────┼──────────────────────────────┼───────────────────┘
                                    │                              │
                     ┌──────────────▼──────────┐        ┌──────────▼──────────────┐
                     │ 批式关联 correlator :8091│        │ 流式关联 stream :8094    │
                     │ 30min 窗口 + 周期扫描     │        │ 30s 滑动窗口 + 事件驱动   │
                     └──────────────┬──────────┘        └──────────┬──────────────┘
                                    │  共用 services/common/ssp_kernel.py
                                    │  （规则定义 R-001~R-007 / 分级 / 富化 / 幂等写入）
                                    └──────────────┬───────────────┘
                                                   ▼
                                          ssp-alerts（_id = sha1(rule|entity)
                                                      → 两引擎天然去重共存）
```

**两条输入通道同源**：`ssp-ecs` 与写入 OpenSearch 的是**同一份 ECS 文档**（Logstash 双写），
因此流式与批式看到的事件字段完全一致，规则口径不会分叉。

## 四、共享关联内核（`services/common/`）

### 4.1 为什么抽取

计划 §八 风险表第一条即"流式与批式规则实现分叉"。对策：**规则定义抽成共享实现，两侧只做执行**。

| 模块 | 职责 | 使用方 |
|---|---|---|
| `ssp_kernel.py` | 规则定义（R-001~R-007）、规则执行、分级/升级、告警组装、幂等写入、资产/情报/地理富化、窗口解析、数据源健康 | correlator（批式）、stream（流式） |
| `threat_intel.py` ＋ `threat_intel_seed.json` | I-04 威胁情报比对（原在 `services/correlator/`，因两引擎共用而移入） | 同上 |
| `kafka_lite.py` | 纯标准库 Kafka 客户端（生产 + 消费 + 位点落盘） | stream、ingest-adapter、运维脚本 |

挂载方式：两服务都只读挂载 `services/common → /srv-common`，并设 `COMMON_DIR/PYTHONPATH=/srv-common`
（本地开发时回退到 `services/common` 相对路径，`make lint` / `python3 services/.../xxx.py --check` 可直接跑）。

### 4.2 内核对外关键接口

```python
kernel.allowed_sources()        # 事件来源白名单（探针 + 已启用外部源）
kernel.evaluate(events, window, assets, threat_mod, engine="batch"|"stream", ingest_by_id=...)
        -> (alert_docs, rule_hits, rule_errors, geo_map)
kernel.upsert_alerts(docs)      # 幂等写入（保留人工处理状态，并集 engines/branches/log_sources）
kernel.run_correlation()        # 批式主流程（correlator 壳直接调用）
kernel.source_health()          # 数据源健康（探针断连判定）
```

**口径不变项**：索引/别名纪律、事件白名单防自反馈、`sha1(rule_id|entity_key)` 幂等 id、
窗口锚定**事件时间**、分级 SLA（P0 秒级 / P1 1min / P2 10min / P3 30min）。

### 4.3 共存标记（本迭代新增字段，`ssp-alerts` 模板已同步）

| 字段 | 含义 |
|---|---|
| `ssp.alert.engines` | 产生/更新过该告警的引擎集合（`batch` / `stream`），合并时取并集 |
| `ssp.alert.first_engine` / `last_engine` | 首个产生 / 最后更新的引擎 |
| `ssp.alert.stream_latency_ms` | 流式引擎**实测时延**：事件入 Kafka → 告警落库（毫秒） |

> ⚠️ 告警索引 `mappings.dynamic=false` → 新字段必须显式声明；且**模板只对新索引生效**。
> `scripts/apply-alerts-template.sh` 已增加对**既有索引**的幂等 `_mapping` 增补，避免"先建后升"丢字段。

## 五、流式关联引擎（`services/stream/`，`:8094`）

### 5.1 输入为什么是 `ssp-ecs`（而不是 `ssp-raw`）

`ssp-raw` 里是**归一前**的原始日志（Filebeat 信封 + 探针私有字段）。若流式引擎自行解析，
等于把 I-01 的 ECS 归一逻辑再实现一遍 —— 正是"规则实现分叉"的来源。因此：

> **Logstash 归一后双写**：OpenSearch（检索 / 批式）＋ Kafka `ssp-ecs`（流式）

收益：① 两侧事件同构，共用一份规则内核；② 流式不必等 OpenSearch 的 `refresh`（1~5s）即可看到事件，时延更低。
`config/logstash/conf.d/99-outputs.conf` 新增 `kafka` 输出（`topic_id=ssp-ecs`，gzip，`acks=1`）。

### 5.2 纯标准库 Kafka 客户端（`kafka_lite.py`）

| 能力 | 实现 |
|---|---|
| 协议子集（全部非柔性版本，避开 compact 编码/tagged fields） | ApiVersions v0、Metadata v1、ListOffsets v1、**Fetch v4**、**Produce v3** |
| 记录编解码 | record batch **v2**（magic=2，含 61 字节批次头）、CRC32C（自建查表，标准库只有 CRC32）、`gzip` 解压（Filebeat 压缩批次） |
| 多分区 | 按 Metadata 选分区 leader；同一 group 订阅主题全分区 |
| 位点 | `FileOffsetStore`：`<OFFSET_DIR>/offsets-<GROUP>.json` 原子落盘（tmp + `os.replace` + fsync） |
| 健壮性 | 尾部半截批次安全截断（不解析、不推进位点）；`OFFSET_OUT_OF_RANGE` 按 `auto_offset_reset` 复位；可重试错误（leader 切换/主题刚建）自动刷新元数据重试；**连接读写全局串行化**（见 §十一 坑 3） |

**为什么不用 pip 客户端**：x86 私有化交付常无外网、无镜像构建能力；标准库实现零依赖，且接口
（`send` / `next_batch` / `commit`）即"换引擎"的替换点（D1 选项 A 的预留）。

### 5.3 滑动窗口（锚定事件时间）

- 窗口右端 `anchor = 缓冲区中最新的 @timestamp`，窗口 = `[anchor - STREAM_WINDOW_SECONDS, anchor]`；
  与批式 `resolve_window` 同口径 —— **历史回放数据不会把实时事件挤出窗口**（I-13 已踩过此坑）。
- 淘汰：超出窗口左端的事件直接丢弃 + 缓冲上限 `STREAM_BUFFER_SIZE`（默认 20000，按到达顺序淘汰）。
- **评估节流**：有事件到达时才评估，且最多每 `STREAM_EVAL_INTERVAL_MS`（默认 1000ms）一次 →
  时延抖动上界 = 节流间隔 + 入库耗时（实测流式段 11~17ms，因空闲后首个事件立即评估）。

### 5.4 位点管理与"不丢事件"

- 订阅 `ssp-ecs`，`STREAM_GROUP=ssp-stream`（位点命名空间），`auto_offset_reset=latest`（实时）；
  **重放**用另一个 group（如 `ssp-stream-replay`，`earliest`）→ 位点互不影响。
- 位点只有在**这批消息成功处理并写入告警后**才提交（默认每 2s + 停机时强制提交）。
- 拉取失败自动重连并**从已提交位点续读**；`fetch` 尾部的半截批次不解析、不推进位点。

### 5.5 幂等与共存（计划 §五.2）

```
_id = sha1(rule_id | entity_key)     ← 与批式完全相同
```
两侧先后命中同一实体 → 只 **update** 不 **insert**；合并时并集 `engines` / `branches` / `log_sources`，
保留人工处理状态（`status` / `first_seen_at` / `response_action` / `generated_at` 被"钉住"）。

### 5.6 观测接口

| 路径 | 内容 |
|---|---|
| `GET /health` | 状态 + 各分区滞后（`lag` 最大者 < 1000 视为健康） |
| `GET /stats` | 消费量、评估次数、窗口事件数/区间、告警新增/更新、**时延 last/p50/max**、位点与末位点、滞后、重连次数、规则异常、来源白名单 |
| `GET /alerts` / `GET /window` / `POST /flush` | 告警列表 / 当前窗口 / 立即评估并提交 |

## 六、外部日志源适配（`services/ingest-adapter/`）

### 6.1 三入口

| 入口 | 端口 | 协议 | 解析产出（放入 `ssp.external.parsed`） |
|---|---|---|---|
| syslog | `5514/udp` | RFC3164 / RFC5424（PRI/facility/severity/hostname/app/**timestamp**），内含 CEF 时一并解析 | 结构化 + 原始文本 |
| CEF | `5515/tcp` | ArcSight CEF（可裸 CEF，也可被 syslog 包裹），`\` 转义与扩展区 `k=v` | `version/vendor/product/version/signature_id/name/severity/extension{src,dst,spt,dpt,proto,act,...}` |
| JSON | `5516` http | `POST /ingest/json?source=&branch=`（对象或数组），兼容 `src_ip/dst_ip/dpt/proto/action/severity/...` 常见键名 | 抽取的通用字段 + 原始 JSON |

### 6.2 职责边界：适配器**只解析 + 打标，不做归一**

```
第三方设备 → ingest-adapter（协议解析 + 打标）→ Kafka ssp-raw（中心汇聚层）
           → Logstash（ECS 归一：40-external.conf）→ OpenSearch ssp-firewall-*
           → 统一检索（ssp-events 别名） + 流式关联（EXTERNAL_SOURCES=firewall,waf）
```

- 信封与 Filebeat 同构（`@timestamp` / `message` / `fields.*`），下游 filter 无需区分来源。
- `@timestamp` 取**进入适配器的时刻**（流式实时性优先，规避设备时钟漂移/无年份的 date 解析坑）；
  设备原始时间保留在 `ssp.external.parsed.timestamp`。
- 分支判定：显式指定 > `ADAPTER_BRANCH_MAP`（按来源 IP 前缀）> 默认 `hq`。
- **新增一类源不改中心**：中心端口、Kafka 汇聚层、索引命名规则（`ssp-<log_source>-日期`）、
  检索别名、关联引擎都不动；只需加一个适配器实例，必要时补一条 Logstash 方言解析。

### 6.3 默认关闭且"零副作用"

- compose 中该服务位于 **profile `external`** → `make up` 不启动；
- 进程内还有 `ADAPTER_ENABLED` 双保险：关闭时**不监听任何端口、不投递任何事件**（EARS State-driven / 用例 N13）；
- 运维入口：`make external-up` / `external-down` / `external-demo` / `external-reset`。

## 七、Logstash 归一（`config/logstash/conf.d/40-external.conf`）

| 方言 | 处理 |
|---|---|
| JSON / syslog 结构化字段 | `parsed.{src_ip,dst_ip,src_port,dst_port,protocol,action,rule_name,rule_id,severity,vendor,product}` → ECS `source.ip` / `destination.ip` / `*.port` / `network.transport` / `event.action` / `rule.*` / `observer.*` |

## 十、验收（EARS + 用例 + 实测结果）

**EARS**

- **Event-driven**：当事件进入 Kafka，系统应在秒级内完成规则匹配并把命中写入 `ssp-alerts`。→ A16
- **Ubiquitous**：流式与批式写同一索引时，同一 `(rule_id, entity_key)` 只产生一条告警（幂等）。→ A17
- **Unwanted**：流式消费者中断应自动重连并从位点续读，**不丢事件**；且不影响批式/大屏。→ N12
- **Event-driven**：外部源日志应打上 `fields.log_source` 与 `fields.branch` 后入库，并可被检索与关联消费。→ A18
- **State-driven**：外部源适配器处于关闭状态（默认）时，不产生任何副作用。→ N13

**用例与实测（`make verify` 21/21）**

| 编号 | 类型 | 实测证据 |
|---|---|---|
| **A16** | 正例 | 原始 suricata 事件投递 `ssp-raw` → 告警落库 **1.05 / 1.07 / 1.11 / 1.19s**（阈值 ≤5s）；`ssp.branch=bj-01` ✓；`engines=['stream']` ✓；流式段 `stream_latency_ms` **11~17ms** |

## 十一、实现期踩坑记录（**最容易复发的部分**）

1. **Kafka v2 记录批次头是 61 字节**，不是 57：`baseSequence` 之后还有一个 4 字节 `recordsCount`
   （官方文档表格未列出，Java 侧 `RECORD_BATCH_OVERHEAD=61`）。漏写会被 broker 判为
   `INVALID_RECORD(87)`（"Invalid batch record count"）；读侧漏算 4 字节则表现为
   `Not a gzipped file (b'\x00\x00')`。
2. **`Produce` v3 响应的 `throttle_time_ms` 在数组之后**（`Fetch` 才在之前）；
   且 `log_start_offset` 自 v5 才有 —— 多读一个 i64 就会整段错位、读出假错误码。
3. **一个 Kafka TCP 连接不能被多线程并发读写**：消费者线程与 HTTP 观测线程共用客户端时，
   响应流交叉 → `NETWORK_EXCEPTION: Bad file descriptor`。已在 `KafkaClient._request` 用全局锁
   把"取连接 → 收发 → 出错丢弃重连"整体串行化（改前必现、改后 10 并发压测 0 错误）。
4. **不要把"混合类型的原始解析结果"直接落成动态映射字段**：`ssp.external.parsed.timestamp`
   先按 `date` 映射、后收到 `Oct 11 22:14:15` → `mapper_parsing_exception` 整条事件被拒（静默丢数据）。
   正解：`{"type":"object","enabled":false}` 只存 `_source` 不索引。
5. **Logstash 不热加载配置**：改 `conf.d/*.conf` 后必须重建容器，否则会误判"解析没生效"。
6. **OpenSearch 的 `_search?refresh=true` 是非法参数（400）**；要立即可见应先 `POST /<index>/_refresh`
   （`_delete_by_query?refresh=true` 与 `_doc?refresh=true` 才是合法的）。
7. **数据源健康判定基准只取探针源**：外部源日志时间口径与探针数据不同（外部是"当下"、探针常为历史回放），
   若混入基准会把探针源误判为 `stale`（会让既有 N1 用例失败）——`source_health` 已按探针白名单取基准。
8. **bash：`$VAR` 紧跟全角字符（如 `）`）会被并进变量名** → `set -u` 下报 `unbound variable`。
   新写脚本一律 `${VAR}`；同时修掉了 `scripts/replay-branch.sh` 的两处同类**既有隐患**（`--down/--up` 路径）。
