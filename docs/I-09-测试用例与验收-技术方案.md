## 3. 反例 / 边界用例（N）

| ID | 场景 | 依据（PRD §10） | 预期行为 | 实测 |
|----|------|------------------|----------|------|
| **N1** | 探针断连 | "大屏标记该数据源异常，**不影响其他源**" | 该源标记 `down`，其他源状态与事件数**不变** | PASS |
| **N2** | 审批超时 | "草稿保留，**不自动提交**" | 长时间不审批，草稿仍 `pending_approval`，iptables **无变化** | PASS |
| **N3** | 落黑失败 | "记录失败原因，告警保持**待处置**，通知运维" | 草稿 `failed`、写入 `approve_failed` 历史；告警保持 `open` 且 `response_action=block_failed:<原因>`；iptables 未新增 | PASS |
| **N4** | Excel 导入失败 | §9 Unwanted "回滚本次导入并报告错误行，不影响存量资产" | HTTP 422、**逐行报错**、资产数**不变** | PASS |
| N5 | 情报平台不可达 | §9 Unwanted | 告警照常、标记"情报未匹配" | 由 **A4** 覆盖（PASS） |

### N1 实现与验证要点
PRD §10 的"探针断连标记"此前**未实现**，本轮补齐：
- **关联服务新增** `GET /sources/health`：按 `fields.log_source` 做一次聚合，取各源最新事件时间，
  与"全局最新事件"比较计算**相对滞后**（`SOURCE_STALE_MINUTES`，默认 15 分钟）：
  `down`=该源无事件 / `stale`=滞后超阈值 / `ok`=正常。用相对陈旧度而非绝对当前时间，
  故**历史数据重放同样适用**。
- **大屏** `ui/dashboard.html` 顶部渲染「数据源 ●suricata ●zeek ●wazuh」健康指示（绿/黄/红）。

验证：删除 `ssp-wazuh-*`（仅令 wazuh 断连）→ health 返回
`{suricata: ok, zeek: ok, wazuh: down}` 且 `overall=degraded`，其他源事件数不变；
`replay-demo.sh` 恢复后三源回 `ok`。

## 6. 实测结果

```
$ python3 scripts/test-cases.py
▶ 正例回归（I-08 A1~A8）          8/8 PASS
▶ N1 探针断连                      PASS
   断连前={suricata:ok, zeek:ok, wazuh:ok} → 断连后={suricata:ok, zeek:ok, wazuh:down}
   其他源事件数 suricata 10→10、zeek 9→9（不变）；恢复后三源 ok
▶ N2 审批超时                      PASS
   等待 20s 后仍待审批 3 条；iptables 规则 ['185.220.101.5']→['185.220.101.5']（不变）
▶ N3 落黑失败                      PASS
   草稿 status=failed；history=[draft_created, approve_failed]
   告警 status=open action=block_failed:挂载 DOCKER-USER 失败: nsenter: can't open '/proc/999999/ns/net'
▶ N4 Excel 导入失败回滚            PASS
   HTTP=422；资产数 10→10（不变）；逐行报错 3 条：
   (3, IP地址, IP 格式非法: not-an-ip) / (3, 重要度, 重要度枚举非法: 超级重要) / (3, 风险评分, 超出 0-100: 999)
```

**结论：正例 8/8 + 反例 4/4 全部通过，PRD §9 验收标准与 §10 边界场景全覆盖。**
