# I-07 态势大屏（4 指标）—— 技术方案

> 版本：v1.0 ｜ 阶段：POC ｜ 对应功能：F-03（态势大屏：攻击地图 / 告警 TOP / 资产热力 / SLA 达成率）
> 关联：`docs/I-03-轻量关联分析-技术方案.md`、`docs/I-06-统一资产库-技术方案.md`、`docs/PRD-...-Phase1.md` §8
> 状态：**已实现并实测通过**

## 1. 目标与范围
把「关联分析 + 资产 + 情报 + SOAR」的成果汇聚成**单页四宫格态势大屏**，让分析师/值班一眼掌握整体态势：

| 指标 | 口径（PRD §8） | 数据来源 |
|---|---|---|
| ① 攻击地图 | 按源 IP 地理定位聚合告警，热力/散点 | `ssp-alerts` 的 `source.geo` / `destination.geo` |
| ② 告警 TOP | 按级别 / 类型 / 资产 TOP N 排序 | `ssp-alerts` |
| ③ 资产热力 | 按资产重要度 × 风险评分着色 | `ssp-assets` + `ssp-alerts` 命中数 |
| ④ SLA 达成率 | 各级别"实际响应时延 ≤ 级别 SLA"的告警占比 | `ssp-alerts.ssp.alert.{generated_at,resolved_at,due_at,sla_seconds}` |

**实现形态**：纯静态单页 `ui/dashboard.html`（vanilla JS，无构建、无第三方库），浏览器**直连 OpenSearch**
（集群已开 CORS）；底部四宫格 + 顶部 KPI 条，15 秒自动刷新。

## 2. 为什么攻击地图需要"GeoIP 全链路"
在此之前，管道里的 `geoip` 过滤器**没有 `database`**（OSS 版 Logstash 不内置地理库），
每次查找都失败 → 触发 `tag_on_failure` → `[source][geo]` 被移除。实测 `ssp-events` 中
`source.geo` 命中数恒为 **0**，攻击地图无数据可画。

因此 I-07 一并补齐了地理富化链路（**这不是纯前端工作**）：

```
探针事件 ──► Logstash geoip(database=DB-IP Lite City)
                ├─ source.geo      （源侧坐标）
                └─ destination.geo （目的侧坐标）
                        │
                        ▼
             correlator.geo_index()  ──► 告警 source.geo / destination.geo
                        │
                        ▼
                   dashboard.html 渲染散点
```

### 2.1 为什么源、目的**两侧**都要富化
PRD 口径是"按**源 IP** 地理定位聚合告警"。但「恶意载荷下载」（R-003）这类事件是
**内网主机主动外联**：`source.ip` 是内网地址、`destination.ip` 才是攻击者。
若只富化源侧，这条最关键的 P0 告警在攻击地图上会**完全消失**。故两侧都富化，
`geo_index()` 只收录"外网且非白名单"的地址（私有/保留地址本就查不到坐标，
显式过滤可避免把 `8.8.8.8` 这类良性对端误标成攻击来源）。

### 2.2 地理库选型
**DB-IP Lite City**（CC-BY-4.0，免费、免账号）。相比 MaxMind GeoLite2 无需 license key。
由 `scripts/fetch-geoip.sh` 下载（**不入库**，`*.mmdb` 已 gitignore），产物：
`config/logstash/geoip/dbip-city-lite.mmdb`，挂载进 Logstash 容器 `/usr/share/logstash/geoip/`。

## 3. 字段映射（ECS 对齐）
原模板把 `source.geo` 直接声明为 `geo_point`——这既不符合 ECS，也无法同时容纳国家/城市维度，
且地理富化一旦生效就会因类型冲突**拒收整条文档**。已改为 ECS 结构（`ssp-ecs-template.json`
与 `ssp-alerts-template.json` 同步）：

```json
"source": { "properties": {
  "ip": { "type": "ip" },
  "geo": { "properties": {
    "location":         { "type": "geo_point" },
    "continent_code":   { "type": "keyword" },
    "continent_name":   { "type": "keyword" },
    "country_iso_code": { "type": "keyword" },
    "country_name":     { "type": "keyword" },
    "region_name":      { "type": "keyword" },
    "city_name":        { "type": "keyword" },
    "timezone":         { "type": "keyword" } }}}}
```
> ⚠️ 字段类型不可原地变更 → 改模板后**必须删除并重建**探针索引与 `ssp-alerts`（见 §7 运维速查）。

## 4. 大屏实现要点
### 4.1 攻击地图底图（自包含，无 CDN 依赖）
生产是**私有化 x86 部署**，不能依赖外部地图服务。故用 `scripts/gen-world-map.py` 把
Natural Earth 1:110m land（公有领域）转成等距圆柱投影的单一 `<path>`，
输出 `ui/assets/world-land.svg`（约 59 KB）作为静态资源。

投影公式（大屏与生成器**共用同一套**，保证底图与散点天然对齐）：
```
x = (lon + 180) / 360 * 1000      y = (90 - lat) / 180 * 500
```
散点：同一 IP 聚合告警数 → 半径随数量放大；颜色取该 IP 上最严重的级别
（P0 红 / P1 橙 / P2 蓝 / P3 灰），外圈加半透明光晕；`<title>` 悬浮显示
`IP · 国家 · 告警数（级别构成）`。底图加载失败时自动退化为经纬网，不白屏。

### 4.2 资产热力
指标口径"重要度 × 风险评分"落地为：**填色由 `risk_score` 决定**（HSL 色相 0°红→120°绿），
**金色加粗描边标记核心资产**，块内直接标注该资产被命中告警数。

### 4.3 SLA 达成率口径（务必看清）
- **判定范围（分母）** = 达标 + 超时。**"待响应"（尚未到截止时刻）不计入分母**，
  否则"还没到期"会被误算成"不达标"。
- 已响应（有 `resolved_at`）：时延 = `resolved_at - generated_at`，`≤ 阈值` 记达标；
- 未响应：`now > due_at` 记超时。
- ⚠️ **P0 阈值量化**：PRD §12 的"秒级"若字面取 0 秒，则 `due_at == generated_at`，
  任何响应都必然超时、达成率恒为 0。POC 将其量化为 **30 秒**（保留"秒级"标签），
  可经 `CORR_SLA_SECONDS` 覆盖。详见 I-03 §5。

## 5. 演示数据集（真实公网 IP，可地理定位）
基础样本 `logs/{suricata,zeek,wazuh}/` 用的是 **RFC5737 文档网段**
（`203.0.113.x` / `198.51.100.x`）——它们**无法被地理定位**，攻击地图永远为空。
为此新增**独立的演示数据集**（不改动基础样本）：

- 生成器：`scripts/gen-demo-data.py` → `logs/demo/{suricata,zeek,wazuh}/`
  共 15 条事件（6+6+3），时间轴锚定在与基础样本**同一关联窗口**内（2026-09-19 03:0x UTC），
  使两者能被同一次 30 分钟窗口一起覆盖。
- 场景："多国团伙攻击"，攻击者分属 RU/KE/DE/BR/VN/IN/CN 等，覆盖 R-001~R-007 全部规则。
- **回放是显式动作**：源数据集**不被直接采集**，由 `scripts/replay-demo.sh` 复制到
  暂存区 `logs/demo-stage/` 后才被 Filebeat 采集（暂存区已 gitignore）。
  这样生产链路保持"只吃真实探针日志"，演示数据随时可 `--reset` 复位。
- 演示事件带 `fields.demo="true"` 标记，可精准清理。

## 6. 实测结果

环境：macOS / Docker Desktop，Compose v5.4.0；OpenSearch + **Logstash 7.16.3** + Filebeat 7.17.23；
地理库 **DB-IP City Lite 2026-09**（元数据 `database_type` 改写为 `GeoLite2-City`，见 §8）。
回放：`./scripts/replay-demo.sh`（基础样本 9 + 演示样本 15 = **24 条**）。

| 环节 | 实测结果 |
|------|----------|
| Filebeat 采集 | 24 条全部投递并被 ack（`added 24 / acked 24`）|
| Logstash 归一 + 地理富化 | 24 条入库；**地理富化外网 IP 8 个**，覆盖 8 个国家 |
| 关联引擎 | 扫描 24 条；R-001~R-007 全命中；写入 19（`created 19 / errors 0`），按实体去重后 **17 条** |
| 告警分级 | P0×12、P1×3、P2×1、P3×1（已含"命中核心资产↑1 档"/"情报命中→P0"升级因子）|
| ① 攻击地图 | 8 个外网 IP 全部带坐标；来源国 **Russia 3 / United States 3 / Germany 1 / Australia 1 / Vietnam 1 / China 1 / United Kingdom 1 / Seychelles 1** |
| ② 告警 TOP | 分级分布 + 规则 TOP5（R-003 4 / R-001 3 / R-002 3 / R-006 3 / R-007 2）+ 受影响资产 TOP5 |
| ③ 资产热力 | 10 项资产按 `risk_score` 着色（红→绿），核心资产金色描边，叠加"命中告警数" |
| ④ SLA 达成率 | 按级别输出 达标 / 超时 / 待响应；**本次回放 P0 12 条全部"超时"，达成率 0%** |

**关于 SLA 0% 的说明（口径正确，非故障）**：达成率 = 达标 ÷（达标 + 超时）。
POC 把 PRD §12 的"P0 秒级"量化为**可测的 30 秒**（`CORR_SLA_SECONDS`，默认 P0=30s）。
回放时告警时钟从 `generated_at`（关联运行时刻）起算，且**无人执行响应动作**，
故 P0 在 30 秒后全部转为"超时"。要得到非零达成率，需经 **I-05 SOAR** 落地响应
（`status=blocked` / 写回 `resolved_at`）——这由 **I-08** 闭环 Demo 补齐。

**攻击地图散点来源**：告警 `related.geo_points` —— 关联引擎在组装告警时汇总的"外网侧"地理点
（覆盖 源 IP、目的 IP，以及 **R-005 外联聚合**涉及的多个目的 IP）。前端据此直接绘图，
**无需**再回查事件层，链路更短。示例（一条 R-005 告警）：

```json
"related": { "geo_points": [
  { "ip": "103.145.13.7", "geo": { "country_name": "Australia", "city_name": "South Brisbane",
      "location": { "lat": -27.473, "lon": 153.014 } } },
  { "ip": "91.240.118.168", "geo": { "country_name": "United Kingdom", "city_name": "London", ... } }
]}
```

> 注：`ssp-alerts` 模板 `dynamic:false`，故 `related.geo_points` 已在模板中**显式声明**
> （`ip` + 嵌套 `geo.location: geo_point`），否则会被静默丢弃。

## 8. 踩坑记录
- 🐞 **【最关键】OSS Logstash 的 geoip 过滤器只认 MaxMind 的数据库类型**：DB-IP 的 mmdb 元数据里
  `database_type = "DBIP-City-Lite"`，Logstash 7.16 白名单里没有它 → 抛
  `Unsupported database type DBIP-City-Lite` 并**停掉整条 pipeline**，事件被**整批丢弃**
  （现象：Filebeat 报 `acked 24`，但 `ssp-events` 恒为 0 —— 极易误判成采集/网络问题）。
  **对策**：用 `scripts/patch-mmdb-type.py` 把元数据 `database_type` 改写为 Logstash 认得的
  `GeoLite2-City`（**数据不变、许可证不变**，只是换个标签）。mmdb 元数据靠"文件末尾回搜魔数
  `\xab\xcd\xefMaxMind.com`"定位而非偏移，故重编码（长度可变）是安全的；改完务必用真正的
  mmdb 读取库（`maxminddb`）复验查询结果与 `node_count/record_size` 完全一致。
- 🐞 **`db-ip.com` 在本机"直连慢、代理不通"**：直连约 23 KB/s 且长连接频繁断开；经本机规则型代理
  （`127.0.0.1:7897`）会 `CONNECT 200` 后立刻 `SSL_ERROR_SYSCALL`（该域名被路由到坏出口）。
  **对策**：改用 jsDelivr 镜像
  `https://cdn.jsdelivr.net/npm/dbip-city-lite/dbip-city-lite.mmdb.gz`
  （wp-statistics/DbIP-City-lite 仓库），**经代理实测约 15 MB/s**，60 MB 库秒下。
- 🐞 **`geoip` 无 `database` 时静默失败**：OSS Logstash 不内置地理库，查找失败 → 打 tag →
  字段被移除，`source.geo` 恒为 0 且**不报错**，极易误判为"前端问题"。
- 🐞 **`source.geo` 直接声明 `geo_point` 与 ECS 国家/城市维度冲突**：地理富化一开就
  `mapper_parsing_exception` 丢文档。改为 `source.geo.location` 为 `geo_point`、其余为 keyword。
- 🐞 **`content-length` 会污染下载器的大小解析**：经代理时响应头首行是
  `HTTP/1.1 200 Connection Established`，206 响应的 `content-length: 1` 出现在
  `content-range: bytes 0-0/<SIZE>` 之前 → 若先匹配 content-length 会把 60MB 文件当成 1B。
  **必须优先解析 `content-range`**。
- 🐞 **db-ip 直连很慢（~36 KB/s）但支持 Range**：16 并发分段可达 ~370 KB/s（约 10×）。
  脚本按段并行下载后拼接，并校验拼接大小 == 远端大小。
- 🐞 **下载失败会留下空的 `.mmdb`**：`gzip -dc > "$OUT"` 的重定向先建文件。
  改为解压到临时文件后**原子 `mv`**。
- 🐞 **upsert 不得刷新 `generated_at` / `due_at`**：否则每轮关联都把 SLA 时钟重置，
  达成率永远 100%。见 I-03 §7。
- 🐞 **`fields.demo` 标记**：Filebeat 自定义 fields 会原样透传到文档，据此可精准清理演示数据。
