# I-10 统一平台整合（把第三方能力收进平台）—— 技术方案

> 背景：第一轮 POC 虽然各组件都跑通了，但**形态上是"门户 + 外链"**——Arkime 流量回溯、
> OpenSearch Dashboards 都是 `target="_blank"` **跳到第三方自己的控制台**，
> 没有达到"在一个平台里统一管理、统一查看"的要求。
>
> 本事项把第三方能力**收进平台**：平台原生提供流量回溯与日志可视化，浏览器只连平台。

---

## 1. 问题定位（为什么之前只能"跳出去"）

| 现象 | 根因 |
|------|------|
| 流量回溯只能外跳 Arkime 控制台 | **Arkime Viewer 用 digest 鉴权，且不发 CORS 头** → 浏览器**无法**从 `:8088` 直接调用 `:8005` 的 API，只能整页跳过去 |
| 日志可视化只能外跳 Dashboards | 平台此前没有原生可视化，只能引到 Dashboards |
| 各页导航各自为政 | 每个页面各写一份 header / `.links`，互相不一致 |

## 2. 定案（与用户确认）

| 取舍 | 结论 |
|------|------|
| 统一形态 | **同站多页 + 统一导航**（保留多个页面，共用一套平台导航，站内切换） |
| 第三方整合方式 | **平台原生重建**（服务端代理 + 平台自有界面），不 iframe、不外跳 |

## 3. 关键修复：Arkime PCAP 导出恒为 0 字节

排查中发现一个**极隐蔽**的问题：`/api/sessions/pcap` 永远返回 `200` 但 **0 字节**。

**根因**：Arkime 的**节点名 = 容器 hostname**，会写进会话与文件记录的 `node` 字段。
取包时用 `SessionAPIs.isLocalView(node)` 判断"是否本节点"，
**不一致就走代理**去 `http://<node>:8005/api/session/<node>/<sid>.pcap`。
容器重建后 Docker 默认把 hostname 变成新容器 ID（实测 `f8f533f3ba8b` → `60184e9a92e6`），
与历史数据里的 node 不匹配 → 代理到一个**已失效的主机名** → `getaddrinfo ENOTFOUND` → 导出为空。
日志里只有一行 `ERROR - Couldn't proxy pcap request ...`，很容易被忽略。

**修复**（`deploy/arkime/compose.yml`）：

```yaml
  arkime:
    hostname: arkime                      # 固定节点名，避免容器重建后漂移
    extra_hosts:
      - "arkime:127.0.0.1"                # 兜底：万一仍走远程取包路径，节点名可解析到自身
```

随后清掉旧数据并用 `scripts/arkime-import.sh` 重新导入（使数据 node 与固定 hostname 一致）：

```bash
curl -X DELETE 'localhost:9200/arkime_sessions3-*' ; curl -X DELETE 'localhost:9200/arkime_files_v30'
./scripts/arkime-import.sh
```

实测：全量导出 **1005 B**、按 `ip==203.0.113.45` 过滤导出 **627 B**，均为合法 pcap；`ENOTFOUND` 归零。

## 4. 平台统一后端（BFF）

新增 `services/portal/portal_server.py`（**纯标准库**，运行时零依赖）：

* 服务端用 **digest 鉴权**访问 Arkime，对浏览器暴露**带 CORS 的简化 API**——浏览器只连平台。
* 把平台友好参数翻译成 Arkime 表达式（`ip=` → `ip == x`、`proto=tcp` → `protocol == tcp`、
  `port=` → `port == x`，时间窗 → `date=<start_ms>|<end_ms>`）。

| 接口 | 说明 |
|------|------|
| `GET /health` | 平台/Arkime 连通性 |
| `GET /api/traffic/health` | Arkime 集群健康 |
| `GET /api/traffic/files` | 已入库 PCAP 文件 |
| `GET /api/traffic/sessions` | 会话列表（ip/proto/port/start/end/limit/offset） |
| `GET /api/traffic/pcap` | 按条件导出 PCAP（二进制流） |

`deploy/portal/compose.yml`（`ARKIME_URL=http://arkime:8005`，映射 `:8093`），已 include 进根 `deploy/compose.yml`。

## 5. 统一导航

`ui/assets/nav.js`：5 个页面（态势大屏 / 统一检索 / **流量回溯** / 资产库 / 拉黑审批）
**共用同一套导航**，自动标注当前页；并在运行时**移除各页遗留的 `.links` 外跳区**。

同时把 4 个页面源文件里指向 `:8005` / `:5601` 的 `target="_blank"` 链接**全部删除**。
（校验：`grep -c "localhost:8005\|localhost:5601" ui/*.html` 全部为 0。）

## 6. 平台内「流量回溯」页

新增 `ui/traffic.html`，全部走平台后端：

* 过滤：IP（源或目的）/ 起始·结束时间 / 协议 / 端口 / 条数
* 会话列表：起始时间、源、目的、协议、字节、包数、摘要（HTTP URI / DNS / TLS）
* 会话详情面板；**导出 PCAP**（按当前筛选条件）
* 侧栏：Arkime 健康 + 已入库 PCAP 文件清单
* **深链**：支持 `traffic.html?ip=…&start=…&end=…`，供告警/检索跳转带入条件

## 7. 平台内下钻（闭环）

| 入口 | 行为 |
|------|------|
| 统一检索结果的外网 IP | 行内「⇄」→ 本平台流量回溯页（带入 IP + 时间窗） |
| 态势大屏攻击地图散点 | 点击 → 本平台流量回溯页（带入该 IP） |

## 8. 实测结果

```
$ curl -s localhost:8093/health | jq .arkime_reachable
true
$ curl -s "localhost:8093/api/traffic/sessions?limit=3"
{"data":[{"source":{"ip":"10.0.0.5"},"destination":{"ip":"203.0.113.45"},...},...],"recordsTotal":3}
$ curl -s -o x.pcap "localhost:8093/api/traffic/pcap?date=-1&ip=203.0.113.45"
x.pcap: pcap capture file, microsecond ts (little-endian) - version 2.4 (Ethernet)   # 627 B

页面可达：dashboard/index/traffic/assets/soar = 200；assets/nav.js = 200
外链残留：ui/*.html 中 localhost:8005|5601 命中数 = 0
```

## 9. 踩坑记录

* 🐞 **Arkime 单节点必须固定容器 hostname**：节点名=hostname 会写进 `node` 字段；
  容器重建后 hostname 漂移 → 取包走"远程代理"→ 主机名解析失败 → **PCAP 导出静默为空**。
* 🐞 **第三方组件能否"进平台"，先看它发不发 CORS**：Arkime 用 digest 且无 CORS 头，
  浏览器直连必然失败 → 必须**服务端代理**（本事项的 BFF）。
* 🐞 **`/api/sessions/pcap` 的 404 有误导性**：不带参数时返回 `404` 但
  `Content-Type` 仍是 `application/vnd.tcpdump.pcap`——据此才能确认"路由存在"，别被 404 骗过。
