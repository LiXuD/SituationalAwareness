# I-02 存储增强与统一检索入口 —— 技术方案

> 关联需求：F-05（OpenSearch 存储 + Logstash 归一富化）、F-07（统一检索入口：跨日志/流量/告警）
> 阶段：POC ｜ 承接：I-01（采集与 ECS 归一）

## 1. 目标
在 I-01 已"统一入湖"的基础上，提供**一个统一的检索入口**——分析师不必知道数据来自哪个探针，即可跨 Suricata / Zeek / Wazuh 的归一事件做时间/关键字/字段过滤、下钻详情；并为后续接入 Arkime 全流量会话预留统一检索面。

## 2. 设计

### 2.1 统一检索目标：别名 `ssp-events`
- 各来源仍分索引存储（`ssp-suricata-*` / `ssp-zeek-*` / `ssp-wazuh-*`），但通过**读别名 `ssp-events` 统一检索**。
- 新索引由 `ssp-ecs` 模板自动挂载别名（模板 `template.aliases`）；
- 历史已建索引用 `scripts/init-alias.sh` 幂等补齐。
- 好处：检索面稳定（不随日索引滚动变化），后续 Arkime 会话索引也可并入或并列。

### 2.2 跨域（CORS）
检索页在浏览器中直连 OpenSearch `:9200` 查询。POC 在 OpenSearch 开启 CORS（`http.cors.*`，生产需收紧来源与鉴权）。

### 2.3 统一检索入口（UI）
- 静态页 `ui/index.html`，由 `nginx` 容器托管于 **http://localhost:8088**。
- 过滤维度：时间范围（15m/1h/24h/7d/全部）、关键字（规则/URL/域名/文件哈希/原始日志）、来源 `event.module`、类型 `event.kind`、源 IP、目的 IP。
- 结果：按时间倒序的**统一列**（时间/来源/类型/源/目的/规则或摘要）+ 点击行看完整事件 JSON。
- 顶部聚合条：按 `event.module`、`event.kind` 实时统计命中分布。
- 设计原则：**不暴露索引细节**，只呈现统一事件面。

### 2.4 CLI 统一检索
`scripts/search.sh "<关键字>"`（支持 `SIP=` / `DIP=` 过滤），用于无界面场景与自动化验证。

### 2.5 富化增强（F-05）
- **GeoIP**：OSS 镜像不含 GeoLite2 库。启用地理富化（攻击地图前置）：
  1. 将 `GeoLite2-City.mmdb` 放入 `config/logstash/geoip/`；
  2. 在 `10-suricata.conf` / `20-zeek.conf` / `30-wazuh.conf` 的 `geoip {}` 中加 `database => "/usr/share/logstash/geoip/GeoLite2-City.mmdb"`；
  3. compose 已挂载 `../config/logstash/geoip` 到容器同名路径。
  未配置时 `source.geo` 不产出（I-01 已修复空对象导致的索引失败）。

### 2.6 流量检索 / PCAP 回溯（Arkime）—— I-02 补全项
**目标**：把全流量会话纳入统一检索面，支持从"归一事件"按 IP/时间 **pivot 到原始 PCAP 抓包**（F-06）。

**接入方式**：Arkime 不走 Logstash，**直连同一 OpenSearch 集群**；会话元数据写 `arkime_sessions3-*`，PCAP 落独立本地卷。

**规划组件（deploy 侧）**
| 组件 | 作用 | 端口 |
|---|---|---|
| arkime (capture + viewer) | 抓包 / 会话入库 / Viewer | 8005 |

**关键配置**
- `db=opensearch`，`elasticsearch=http://opensearch:9200`，`prefix=arkime`，`viewerHost` 指向本机。
- 采集接口：POC 单机可用 `-r` 读取 **PCAP 回放**（正好配合 I-08 验收的真实流量回放）；生产用 `af_packet` 抓真实网卡。
- PCAP 目录挂载独立卷 `arkime-pcap`，与 `os-data` 分离。

**与统一检索面的融合**
- 检索页新增「流量会话」页签，查询 `arkime_sessions3-*`；
- 从任一归一事件（`source.ip`/`destination.ip` + `@timestamp`）一键 pivot 到 Arkime Viewer（`/sessions?expression=ip==<ip>`）。

**验收**
- `_cat/indices/arkime_sessions3-*` 有数据；
- 检索页「流量会话」可查到会话；pivot 能打开对应时段 PCAP。

**状态**：I-02 补全项 —— **已部署并实测通过（2026-09-19）**。Arkime v5.8.1 已入栈（容器 `ssp-arkime`，Viewer :8005），与 OpenSearch 同集群，会话索引 `arkime_sessions3-231114` 已产出真实数据。

**落地配置（config/arkime/config.ini）**
```ini
db=opensearch
elasticsearch=http://opensearch:9200
prefix=arkime_                 # 实际前缀带下划线，OpenSearch 无鉴权故 userName/password 留空
passwordSecret=ssp-poc-arkime-secret   # Viewer 本地用户口令哈希用
viewerHost=0.0.0.0:8005
pcapDir=/opt/arkime/pcap       # 挂独立卷 arkime-pcap
```
Viewer 未显式设 `authMode`，Arkime 默认 **digest** 鉴权（日志会提示 `Using authMode=digest`）——用 Basic 会 401，须用 `curl --digest`。

**实测结果（2026-09-19 本机真实起栈）**
- 镜像：`ghcr.io/arkime/arkime/arkime:v5.8.1` 拉取成功（多架构，x86 解析为 amd64）。
- 初始化：`scripts/arkime-init.sh` 可重跑；`db.pl init --ifneeded` 建出 `arkime_fields_v30`(398 docs) / `arkime_users_v30`(1) 等；`arkime_add_user.sh --createOnly` 建出 `admin`(superAdmin)。
- 会话入库：`scripts/arkime-import.sh` 回放 `samples/pcap/sample.pcap`（11 包 / 3 条流 → `packets: 11`），产出 `arkime_sessions3-231114`（**3 docs**），且**位于同一 OpenSearch 集群**。
- Viewer 回溯：digest 鉴权后 `GET /api/sessions` 返回 `recordsTotal = 3`，可列出 C2 流（`10.0.0.5:41952 → 203.0.113.45:80`，183B，`http.uri = 203.0.113.45/c2/beacon?host=10.0.0.5`）、DNS、CDN 三条会话。
- **字段命名利好**：Arkime 5.x 会话字段为 **ECS 对齐**（`source.ip` / `source.port` / `destination.ip` / `destination.port` / `ipProtocol`），与 `ssp-*` 归一事件同名，**pivot 无需字段映射**。

**🔧 实测修正的五个问题**
1. **样本 pcap 缺以太网头**：生成器定义了 `eth()` 却从未调用，帧从 IPv4 头开始，而 pcap 全局头声明 `linktype=1 (Ethernet)` → libpcap 按以太网解析读到非法 ethertype，Arkime 丢弃全部包（`packets: 0`、无会话索引）。已按目的 IP 补以太网头。
2. **时间戳单位错误**：生成器 `t += dt`（`dt=100000`）把微秒当秒累加，每个包跳约 1.16 天，会话被写进 8 个按天索引（`arkime_sessions3-231119`…`231126`）。已改为 `t += dt / 1e6`，回归为单一日索引。
3. **健康检查误判**：busybox `wget` 遇 401 时退出码是 **6（认证失败）**而非 8，原判定漏掉 6 → 容器永久 `unhealthy`（`FailingStreak: 20`）。已放行 6 并加 `start_period: 40s`。
4. **本机 curl 走代理**：请求行变成绝对 URI（`GET http://localhost:8005/...`），Express 判为 `400 Bad Request`。`arkime-*.sh` 已统一加 `--noproxy '*'`。
5. **Compose 插值吃掉了 healthcheck 的 shell 变量**：`c=$?` 触发 `WARN: The "c" variable is not set`，Compose 解析期把它替换为空串，容器里实际执行的是 `c= ; [  -eq 0 ] || ...`（语法错误）→ 健康检查永远失败。必须写成 `$$c` / `$$?` 才能把字面 `$` 传给容器 shell。修复后 `Status = healthy`（`FailingStreak = 0`）。

**⚠️ 已知限制 / 未做**
- POC 用 **PCAP 回放**（`capture -r`），**未接真实网卡采集**（生产应改 `af_packet`）；PCAP 保留策略与轮转未做。
- Arkime 自身 GeoIP 库未提供（日志有 `No Geo Country file / No Geo ASN file` 告警），Arkime 侧地理富化未启用。
- 检索页「流量会话」页签与「事件→会话一键 pivot」尚未实现（见下一节）。
