## 一、背景与问题

用户验收指出平台「不像一个项目」：后端没有数据库、前端登录是"假登录"、本质仍是各开源组件各管各的。经诊断，问题成立：

| 数据 | 原存储 | 问题 |
|---|---|---|
| 用户/账号 | `users.json` 手写文件 | 无管理界面、改密码靠脚本 |
| 登录会话 | portal 进程内存字典 | **重启即掉线** |
| 资产 | OpenSearch `ssp-asset` | 借用 ES 当业务库 |
| SOAR 草稿/黑名单 | OpenSearch `ssp-soar-drafts` | 状态机数据放检索库 |

根因：早期为"纯标准库 + POC 轻量"刻意绕开了数据库，导致没有自有业务数据层。

## 二、目标与方案

**目标**：引入平台自有业务数据库，把业务对象（用户/会话/资产/审批/黑名单/配置/审计）统一收口；事件/告警/流量等检索型数据继续留在 OpenSearch/Arkime（本职工作，不该动）。

**选型**（用户拍板）：SQLite 落地 + PostgreSQL 预留。
- SQLite：Python 标准库 `sqlite3`，零新增依赖、零部署，契合 x86 私有化。
- PostgreSQL：通过 `PLATFORM_DB=postgresql://...` 平滑切换，仅需 `pip install psycopg[binary]`，业务代码零改动。

## 三、架构分层

```
统一前端 SPA（ui :8088）
        │ 同源反代 /api
统一业务后端（portal :8093）—— 身份/会话/资产/审批/审计/统一授权
        ├─ 业务库 SQLite（users/sessions/assets/soar_drafts/blacklist/config/audit_log）
        └─ 检索与时序层（保留）：OpenSearch 事件·告警 / Arkime 流量·PCAP
落黑执行器（soar :8092，privileged）—— 仅 iptables 系统级操作
采集管道（保留）：Filebeat→Logstash→correlator
```

## 四、数据库设计（`services/portal/db.py`）

- **双后端抽象**：`backend()` / `qmark()`（SQLite `?`、PG `%s`）；SQLite 用**单连接+全局锁**（避免 Docker bind-mount 多连接锁竞争）+ `busy_timeout`。
- **7 张表**（主键用业务自然键、时间用 epoch 秒，保证双后端兼容）：

| 表 | 关键字段 |
|---|---|
| users | username(PK)、role、salt/hash/iterations(PBKDF2)、status |
| sessions | token(PK)、username、expires_at（**持久化会话**） |
| assets | asset_id(PK)、ip、importance/score、risk_score、tags(JSON) |
| soar_drafts | id(PK)、entity、grade、status、payload(完整doc+history) |
| blacklist | entity(PK)、action、status |
| config | key(PK)、value |
| audit_log | id(PK)、username、action、target、detail、ip |

- `scripts/init-db.py`：建表 + 种子账号（迁入 users.json；口令取自 `deploy/.env` 的
  `SSP_<账号>_PASSWORD` / `SSP_DEFAULT_PASSWORD`，仓库内不保存任何可用口令）。

## 五、改造内容

1. **portal 升级为业务后端**：真登录（会话落 sessions 表，**重启不掉线**）、审计落 audit_log；`/api/asset/*`、`/api/soar/*` 直接处理业务，不再透传。
2. **资产收口**（`portal/assets.py`）：CRUD + Excel 导入「全成或全败」事务回滚；`asset_server.py` 退役（compose 移除），前端路径 `/api/asset/api/assets*` 零改动。
3. **SOAR 收口**（`portal/soar.py`）：草稿状态机 + 黑名单落 SQLite；`soar_server.py` 降级为**落黑执行器**（`/soar/block/apply|remove|list`），iptables 仍由特权容器执行（合理分工）。
4. **数据迁移**：OpenSearch `ssp-asset` 10 条资产迁入 SQLite。
5. **回归脚本适配**：`test-cases.py`(N2/N3/N4)、`acceptance-demo.py`(A6/A7/A8/reset) 改经 portal + SQLite。

## 六、实测结果

- **回归 5/5 通过**：正例 A1~A8 8/8（含审批落黑回写、大屏四视图）+ 反例 N1~N4 4/4（探针断连/审批超时/落黑失败/Excel 回滚）。
- 资产 CRUD + 合法导入 200、非法导入 422+回滚（10→10 不变）、analyst 写 403。
- SOAR generate 3 草稿、approve 落库、blocks 落 SQLite、analyst 403。
- **会话持久化**：portal 重启后同一 cookie 调 `/api/auth/me` 仍 200（真登录）。
- 登录压力 10/10、错误密码 401、登出失效、审计落库。
