# 备份与恢复

> 适用提交：`d7d5916` ｜ 说明：本平台**业务对象在平台自有库，事件/告警/流量在 OpenSearch/Arkime**，
> 备份需同时覆盖「库 + 检索数据 + 配置」。

---

## 1. 需要备份的对象

### 1.1 业务数据库（**最高优先级**）

| 对象 | 位置 | 说明 |
|---|---|---|
| SQLite 业务库 | `data/ssp.db`（宿主，gitignore） | 用户/会话/资产/候选池/分支/审批/黑名单/配置/审计 |
| PostgreSQL（可选后端） | `pg-data` 卷 | 仅使用 `make pg-*` 时有 |

> SQLite 备份即拷贝 `data/ssp.db`（业务量小，秒级）；建议在低峰期做，避免写锁竞争。

### 1.2 检索/流数据卷

| 卷 | 内容 |
|---|---|
| `os-data` | OpenSearch 索引（事件 + 告警） |
| `kafka-data` | Kafka 主题与位点（含 `ssp-raw` 原始日志、`ssp-ecs` 归一事件流） |
| `stream-offsets` | 流式引擎消费位点（`/var/lib/ssp-stream/offsets-<group>.json`） |
| `arkime` / `arkime-pcap` | Arkime 会话库与抓包数据 |

> 演示环境可用「重建」替代备份（数据可由 `make demo` / `make branch-demo` 重新回放）；生产需按卷备份。

### 1.3 配置文件

| 对象 | 位置 |
|---|---|
| 运行时配置 | `deploy/.env`（**含口令，务必纳入加密备份**） |
| 索引模板 | `config/opensearch/*.json` |
| Logstash 管道 | `config/logstash/conf.d/` |
| Arkime 配置 | `config/arkime/` |
| 编排文件 | `deploy/**` |

## 2. 备份命令示例

```bash
# 业务库（SQLite）
cp data/ssp.db "backup/ssp.db.$(date +%Y%m%d%H%M%S)"

# 配置 + 编排
tar czf "backup/config-$(date +%Y%m%d).tgz" deploy/.env config/ deploy/compose.yml deploy/*/

# 数据卷（演示环境可选；生产建议用卷快照或 docker run 侧车打包）
docker run --rm -v ssp-poc_os-data:/data -v "$PWD/backup":/backup alpine \
  tar czf /backup/os-data-$(date +%Y%m%d).tgz -C /data .
```

> 卷名带 Compose 项目名前缀（默认 `ssp-poc_`），用 `docker volume ls` 确认。

## 3. 恢复

**恢复顺序**（依赖关系从下到上）：

```bash
# 1) 停服务
make down

# 2) 恢复配置
tar xzf backup/config-YYYYMMDD.tgz -C .

# 3) 恢复业务库（SQLite）
cp backup/ssp.db.YYYYMMDDHHMMSS data/ssp.db

# 4) 恢复数据卷（若有备份）
docker run --rm -v ssp-poc_os-data:/data -v "$PWD/backup":/backup alpine \
  tar xzf /backup/os-data-YYYYMMDD.tgz -C /data
# （kafka-data / stream-offsets / arkime / arkime-pcap 同理）

# 5) 启动 + 下发模板 + 校验
make up
make templates
make health
```

**注意**
- `stream-offsets` 卷与 `kafka-data` 必须**成对恢复**：位点指向 Kafka 主题位点，单独恢复其一会导致
  消费从错误位点开始（丢/重）。
- SQLite 恢复后容器侧有约 1s 可见延迟（bind mount 传播），等 1s 再校验。

## 4. 演示环境重建（无备份时的兜底）

```bash
make down
docker compose -f deploy/compose.yml down -v      # 删除全部数据卷（**危险，仅演示环境**）
make init && make up && make templates
make demo && make branch-demo                     # 重新回放演示/分支数据
make verify                                       # 校验闭环
```

## 5. 备份策略建议

| 频率 | 对象 |
|---|---|
| 每次变更后 | `deploy/.env`（含口令）与 `config/`、`deploy/**` |
| 每日 | `data/ssp.db` |
| 每周 | 数据卷（若业务数据不可重放） |
| 口令轮换后 | 立即重新备份 `deploy/.env` |

> `deploy/.env` 含口令，**务必加密/受限存储**；不要与代码同仓提交（已 gitignore）。
