# 故障排查手册

> 汇编项目已实际踩过的坑（症状 → 根因 → 处置）。适用提交：`d7d5916`。
> 来源：各迭代技术方案「风险/坑」小节 + 项目记忆沉淀。每条均可复现。

---

## 1. Arkime 会话/PCAP 为 0 字节

- **症状**：Arkime Viewer 有会话但 PCAP 下载 0 字节、回放无流量。
- **根因**：容器 `hostname` 与 `config.ini` 的 `pcapDir`/节点名不一致，Arkime 找不到抓包目录。
- **处置**：核对 `deploy/arkime/compose.yml` 的 `hostname` 与 `config/arkime/config.ini`；重建 `make up --force-recreate arkime`。

## 2. Logstash pipeline 被 GeoIP 数据库停掉

- **症状**：Logstash 反复重启，日志报 GeoIP 数据库不可用。
- **根因**：OSS Logstash 无 GeoLite2，需 **DB-IP Lite City**；且其 `database_type` 不在 Logstash 白名单。
- **处置**：`scripts/fetch-geoip.py` 下载后**必须**跑 `scripts/patch-mmdb-type.py` 把 `database_type` 改为 `GeoLite2-City`。

## 3. 关联产出为零（回放/演示场景）

- **症状**：`make demo` 后 `make verify` 的 A2 关联告警为 0。
- **根因**：关联窗口**锚定墙钟**时，历史回放数据时间陈旧，全部落在窗口外。
- **处置**：窗口已改为**锚定事件时间**（`resolve_window` 的 `replay` 模式）；排查时先看 `/correlate` 返回的 `window.mode`。

## 4. 宿主直写 SQLite，容器读到陈旧/报错

- **症状**：脚本在宿主改 `data/ssp.db`，容器内查询不到或报 `disk I/O error`。
- **根因**：① Docker Desktop bind mount 对容器进程约 **1s 传播延迟**（脚本已 `sleep(DB_SYNC_WAIT)`）；
  ② 受限环境禁止删除 `ssp.db-journal` → commit 报 `disk I/O error`（测试夹具已改用连接级 `journal_mode=MEMORY`）。
- **处置**：写库后等待 ≥1s；排查"写进去没生效"先 `docker exec` 进容器核对文件。

## 5. `make pg-init` 报「缺少驱动」

- **症状**：宿主跑 `make pg-init` 报缺 `psycopg`。
- **根因**：PG 驱动只预装在 **portal 镜像**内，宿主 Python 没有。
- **处置**：`make pg-init` 已改为在宿主用 `deploy/.env` 拼 DSN 后调 `init-db.py`（SQLite 走宿主 sqlite3）；
  或改在 portal 容器内执行（`docker exec ssp-portal python3 scripts/init-db.py`）。

## 6. 前端经 nginx 访问被 Express 判 400

- **症状**：本机 `curl localhost:8088` 或服务接口返回 `400 Bad Request`。
- **根因**：curl 走代理发出**绝对 URI 请求行**（`GET http://...`），Express 拒绝。
- **处置**：本机访问一律 `curl --noproxy '*'`；脚本内已统一加 `--noproxy '*'`。

## 7. Compose 配置被 `$VAR` 插值改坏 / 健康检查永久失败

- **症状**：容器启动后 healthcheck 一直失败、`docker compose config` 有 `WARN: ... variable is not set`。
- **根因**：Compose 在**解析期**插值 healthcheck/command 里的 `$VAR`。
- **处置**：要传字面 `$` 写 **`$$`**（如 `c=$$?`）。

## 8. busybox `wget` 鉴权类 healthcheck 误判失败

- **症状**：需鉴权的服务健康检查误报不健康。
- **根因**：busybox `wget` 遇 401 的退出码是 **6**（不是 8）。
- **处置**：healthcheck 对 401 一并放行（`|| [ "$?" = 6 ]`）。

## 9. 分支断链判定 / 未登记分支

- **症状**：分支列表出现 `unregistered`，或断链分支未判 `no_data`。
- **根因**：分支需在 `branches` 表登记（`make init` 种子 hq/sh-01/bj-01）；事件带 `ssp.branch` 但未登记 → `unregistered`。
- **处置**：portal「分支管理」登记；断链演练用 `make branch-down B=<id>`。

## 10. 流式引擎位点 / 消费问题（I-14）

- **症状**：`make stream-status` 显示 `lag` 持续增长、或告警没有 `engines:['stream']`。
- **根因**：① 位点文件按 group 隔离，改了 `STREAM_GROUP` 却没换 `STREAM_OFFSET_DIR` 下的文件；
  ② Logstash 的 `ssp-ecs` 双写未生效（改了 conf 没重建 logstash）。
- **处置**：核对 `STREAM_GROUP` / 位点文件；改 `config/logstash/conf.d/*` 后**必须重建 logstash**（不热加载）。

## 11. 一个 Kafka 连接多线程并发 → `Bad file descriptor`

- **症状**：流式引擎日志报 `NETWORK_EXCEPTION: [Errno 9] Bad file descriptor`。
- **根因**：一个 TCP 连接被消费者线程与 HTTP 观测线程并发读写，响应流交叉。
- **处置**：已在 `kafka_lite._request` 加全局锁串行化（改后不复现）。

## 12. 往已有初始提交的仓库推本地独立历史

- **症状**：`git push` 被拒（non-fast-forward）。
- **根因**：远端有 `Initial commit`（LICENSE），本地历史无共同祖先。
- **处置**：`git merge --allow-unrelated-histories origin/main` 后推；**不要强推覆盖**。
  `git rebase origin/main` 在无共同祖先场景易残留 `.git/rebase-merge`（用 `git checkout -f main` 无损恢复）。

## 13. OpenSearch `_search?refresh=true` 报 400

- **症状**：查询带 `?refresh=true` 返回 400。
- **根因**：`_search` 不接受 `refresh` 参数。
- **处置**：先 `POST /<index>/_refresh`，再 `_search`（`_delete_by_query?refresh=true` 与 `_doc?refresh=true` 才合法）。

## 14. 受限环境（禁删文件）下 SQLite / py_compile 报错

- **症状**：`make verify` 里 A9~A11/N6 报 `disk I/O error`；`make lint` 报 `Operation not permitted`。
- **根因**：平台沙箱禁止删除 `*.db-journal` / `__pycache__` 文件。
- **处置**：夹具 SQLite 用连接级 `PRAGMA journal_mode=MEMORY`；`make lint` 已改用零副作用的 `scripts/lint.py`。

## 附：通用排查顺序

1. `make ps` 看哪些容器异常 / `healthy` 状态；
2. `docker logs <容器> --tail 100` 定位首个报错；
3. 改过源码/配置 → 确认是否 `--force-recreate` 重建、Logstash 是否已重建；
4. 本机访问接口 → 一律加 `--noproxy '*'`；
5. 仍无头绪 → 对照本手册与 `docs/PROJECT-STATE.md` §4「关键约定与已知坑」。
